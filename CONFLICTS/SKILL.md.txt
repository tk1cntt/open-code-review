42-**Argument handling:**
43-
44-- **Background context** (RECOMMENDED): use `--background "context"` or `-b "context"` to provide business context for better review quality
45-- **Default** (no user arguments): reviews staged, unstaged, and untracked changes (workspace mode)
46-- **Specific commit**: use `--commit` or `-c` to review a single commit against its parent
47-- **Branch comparison**: use `--from <ref>` and `--to <ref>` to review diff between two refs
48-- **Effort**: `--effort low|medium|high` (default `medium`) sets review rounds (1/2/3). More rounds improve recall at higher cost
49-- **Timeout**: effective timeout per review group = `--timeout` × review rounds. Default `--timeout 15` with default effort `medium` (2 rounds) gives 30 minutes; `low`/`high` give 15/45 minutes.
50-- **Concurrency**: default concurrency is 8 file workers; reduce with `--concurrency <n>` if rate limits are hit
51-- **Grouping / max-tools**: files are grouped semantically before review. `--max-tools` is the per-group tool-call cap; values 1–49 are clamped up to 50
52-- **Preview mode**: use `--preview` or `-p` to preview which files will be reviewed without running the LLM

54-- **No filter**: `--no-filter` keeps all comments and skips the LLM post-filter pass
55-- **Output file**: `--output <path>` / `-o` writes results to a UTF-8 file (default: stdout)
56-- **Resume**: use `--resume <session-id>` to reuse completed results and retry failed files from a previous session

260-## Gotchas
261-
262-- **LLM must be configured first** — `ocr review` will fail loudly if no LLM is reachable. See the Troubleshooting section below if this happens.
263-- **Working directory matters** — `ocr review` operates on the Git repo at the current directory. Use `--repo /path/to/repo` to run from elsewhere.
264-- **Untracked files are reviewed in workspace mode** — running bare `ocr review` includes staged, unstaged, *and* untracked changes. Stage selectively if you want narrower scope.
265-- **Large diffs may hit token limits** — files with very large diffs may be truncated. The default `MAX_TOKENS` is 58888 per request.
266-- **Plan phase triggers at 50 lines** — diffs exceeding 50 changed lines run an extra risk-analysis phase before main review. This adds latency but improves quality.
267-- **Don't pass `--audience human`** — it streams progress UI that pollutes output. Always use `--audience agent`.
268-- **Comment language follows config** — set `language` config to `English` or `Chinese` (default: Chinese) to control review comment language.
